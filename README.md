# bitrix-install.sh

Установщик демосайта «1С-Битрикс: Управление сайтом» в Docker на Ubuntu 24.04.
Доводит чистый сервер до состояния «открой мастер установки в браузере».

Скрипт на bash, 691 строка, без зависимостей кроме python3 (есть в Ubuntu).

> **Статус:** отдельные части проверены вживую — проверки сервера, удаление,
> правка compose-файла. Полный проход от чистого сервера до установщика после
> последних правок ещё не прогонялся. Запускайте на тестовой машине.

Рядом лежит [INSTRUCTION.md](INSTRUCTION.md) — те же шаги вручную, без скрипта.

## Как скачать

```bash
curl -fsSL https://raw.githubusercontent.com/Aizenhaim/bitrix-docker-install/main/bitrix-install.sh -o bitrix-install.sh
less bitrix-install.sh      # посмотрите, что он делает
bash bitrix-install.sh
```

Не запускайте через `curl ... | bash` одной строкой: скрипт ставит пакеты и
правит системные каталоги, такое стоит сначала прочитать.

## Что он делает

Ставит Docker из официального репозитория, разворачивает окружение
`bitrix-tools/env-docker`, вырезает из него ненужные контейнеры, прописывает
пароли базы данных, поднимает стек и кладёт `bitrixsetup.php` в корень сайта.

Чего он **не** делает: не проходит мастер установки в браузере. У мастера нет
неинтерактивного режима — шесть экранов человек проходит сам. Скрипт в конце
печатает все пароли и параметры, которые там понадобятся.

## Требования

| Что | Значение | Проверяется |
|---|---|---|
| ОС | Ubuntu 24.04 | да |
| Права | root | да |
| Архитектура | amd64 | да |
| Свободное место | от 10 ГБ | да |
| Оперативная память | от 3,5 ГБ | да |

| Доступ в интернет | github.com, download.docker.com, www.1c-bitrix.ru | да |
| python3 | любой | да |

Скрипт откажется работать, если что-то из этого не выполнено, и покажет
красный крестик напротив причины.

## Запуск

```bash
bash /root/projects/bitrix-install.sh
```

Откроется меню. Отдельный режим «только проверить сервер, ничего не ставить»:

```bash
bash /root/projects/bitrix-install.sh --check
```

Возвращает код 0, если все проверки пройдены, и 1, если нет — годится для
автоматизации.

## Меню

```
   ПОДГОТОВКА
   [1]  Проверить сервер          15 проверок по четырём группам
   [2]  Настройки                 порт, пароли, набор контейнеров
   УСТАНОВКА
   [3]  Установить                шесть шагов, разблокируется после [1]
   [4]  Переустановить            очистка и установка заново
   ПОСЛЕ УСТАНОВКИ
   [5]  Состояние сервера         что стоит и что работает
   [6]  Параметры для мастера     пароли и ссылки
   ОПАСНОЕ
   [7]  Удалить сайт и окружение  с Docker или без
   [0]  Выход
```

Пункт 3 заблокирован, пока не пройдёт проверка. При смене порта в настройках
статус проверки сбрасывается — порт входит в чек-лист.

### [2] Настройки

Порт сайта (по умолчанию 8588, https на 8589), пароль MySQL root, пароль
пользователя `bitrix`, логин и пароль администратора сайта, набор контейнеров.

Пароли генерируются автоматически, можно ввести свои: латиница, цифры,
`_ . -`, от 8 символов.

Логин и пароль администратора скрипт **не применяет** — их вводит человек в
мастере. Скрипт только хранит и печатает их в конце, чтобы было что копировать.

### Наборы контейнеров

| Набор | Контейнеры | Образы |
|---|---|---|
| минимальный | nginx, php, mysql, cron | ~2,5 ГБ |
| полный | плюс redis, memcached, sphinx, push×2, ssl | ~3,1 ГБ |

В обоих случаях выключаются `postgres` (вторая база, 642 МБ) и `lego`
(клиент Let's Encrypt, занимает порт 80).

Минимальный набор покрывает требования вендора: PHP 8.2, nginx, MySQL 8.0.
Redis, memcached, Sphinx и push-сервер в требованиях не значатся.

### [4] Переустановить

Для случая, когда установка оборвалась: пропала связь, зависла загрузка
образов, мастер упал. Останавливает контейнеры, стирает тома и каталог
окружения, прогоняет проверку и ставит заново. Docker и образы остаются,
поэтому повторный проход занимает минуты три вместо пятнадцати.

### [7] Удалить

Два варианта. «Только Битрикс» — контейнеры, тома, каталог; Docker остаётся.
«Вместе с Docker» — плюс все пакеты, образы, репозиторий, ключ, группа,
мост `docker0`, и в конце пять проверок, что следов не осталось.

Подтверждение: слово `УДАЛИТЬ` или `УДАЛИТЬ ВСЁ` целиком.

## Шесть шагов установки

| Шаг | Что происходит | Время |
|---|---|---|
| 1/6 | apt update, ставятся ca-certificates, curl, gnupg, git, unzip | ~1 мин |
| 2/6 | ключ и репозиторий Docker, установка Docker и Compose, автозапуск | ~1 мин |
| 3/6 | скачивание архива окружения (693 МБ) и распаковка | ~1 мин |
| 4/6 | пароли в `.env_mysql`, правка compose, правка конфига nginx | мгновенно |
| 5/6 | скачивание образов, запуск контейнеров, ожидание nginx и базы | 5–15 мин |
| 6/6 | `bitrixsetup.php` внутрь контейнера php | ~5 сек |

Молчаливые шаги показывают крутилку со счётчиком секунд. Циклы ожидания
пишут, сколько прошло и сколько скрипт готов ждать.

## Что остаётся на сервере

| Что | Где |
|---|---|
| Пакеты Docker | системные, ~400 МБ |
| Служба `docker` | в автозапуске |
| Репозиторий и ключ | `/etc/apt/sources.list.d/docker.list`, `/etc/apt/keyrings/docker.asc` |
| Образы | `/var/lib/docker` |
| Окружение | `~/1c-bitrix/env-docker-main/` |
| Оригиналы правленых файлов | `docker-compose.yml.orig`, `confs/nginx/conf.d/default.conf.orig` |
| Тома с данными | `dev_www_data`, `dev_mysql_lib_data` и другие |
| Архив | `~/1c-bitrix/main.zip` — в конце скрипт предлагает удалить |

Пароли базы лежат в `~/1c-bitrix/env-docker-main/.env_mysql`, права 600.

## Две правки, без которых окружение не работает

**PostgreSQL.** Комментируется блок сервиса и строка `- postgres` в
`depends_on` у `php`. Без второй правки Compose откажется запускаться:
`php` будет ссылаться на несуществующий сервис.

**push-конфиги nginx.** Если выключены контейнеры `push-sub` и `push-pub`,
скрипт комментирует подключение `inc/push.conf` и `inc/push_secure.conf` в
`confs/nginx/conf.d/default.conf`. Иначе nginx падает с
`host not found in upstream "push_sub"` и уходит в цикл перезапуска, а порт
сайта никто не слушает. Compose-файл при этом остаётся валидным, поэтому
обычная проверка конфигурации такую поломку не ловит — скрипт отдельно
проверяет, что nginx реально отдаёт страницы.

Сервисы ищутся по именам, а не по номерам строк, поэтому правки переживут
обновление окружения.

## Если что-то пошло не так

| Сообщение | Причина | Что делать |
|---|---|---|
| `Не пройдено: N` | не выполнены требования | смотреть красные крестики в чек-листе |
| `compose-файл стал некорректным` | правка сломала YAML | оригинал в `docker-compose.yml.orig` |
| `nginx не отвечает на порту` | конфликт портов или битый конфиг | скрипт печатает последние 15 строк лога nginx |
| `База не поднялась за 5 минут` | не стартовал MySQL | `docker compose logs --tail=50 mysql` |
| `Ввод закончился — выход` | скрипт запущен не в терминале | запускать интерактивно |

После обрыва на любом шаге — пункт 4, он чистит и ставит заново.

## Ограничения

Скрипт рассчитан на один экземпляр окружения: каталог `~/1c-bitrix` и префикс
контейнеров `dev_` зашиты в коде. Поставить рядом **вторую независимую
установку Битрикса** нельзя — контейнеры столкнутся именами.

Это не про многосайтовость. Несколько сайтов внутри одной установки Битрикс
делает штатно: общая база, общая админка, те же контейнеры, у каждого сайта
свой шаблон и своя структура. Настраивается в админке, скрипт для этого не
нужен. Единственное, что может потребоваться от сервера, — добавить
`server_name` в конфиг nginx, если сайты живут на разных доменах. При
разделении по папкам (`/site2/`) сервер не трогается вообще.

Проверен на Ubuntu 24.04.5 с Docker 29.9.1 и окружением от 16.10.2026.
